# Customize SuperSurfer

The Customize SuperSurfer navigation area is the entry point for changing this app. Its linked source checkout determines the repository; a selector appears when multiple source checkouts are connected. Source projects are hidden from the Projects tree but remain real scoped records, accessible through Open source. Check that project's `repo` is the intended fork before editing. The desktop client's local checkout is a separate path and may be on a different machine. Neither source edits nor a remote build change the running client by themselves.

Each submitted main-page idea creates its own task-backed worker conversation and sends the user's text there. New chat opens an empty coding conversation without a feature form. Use the Agents list to return to earlier ideas; creating/switching a chat does not stop others or grant new execution authority. For a visual change, start a configured preview for that project when the workflow supports one, then direct the user to the Visual preview area in Customize. It displays active preview actions from project activity and has a Refresh control. A preview of a web page or component is evidence for that surface only; do not claim it is the installed desktop app. If no configured preview can represent the change, explain the limitation and show the source diff or a local packaged-app check instead.

Map a request to the installed source version first. `ui/` owns workspace pages and agent chat; `server/` owns API actions, work items, surfboards and policy; `desktop/` owns Electron windows, local connection, native dialogs and installation. Read `AGENTS.md` and `.agents/contributing.md` for contribution checks and deliverables. Re-read files before patching because this repository is shared with the user and other agents. Preserve unsaved editor buffers and unrelated changes.

For a functionality change, implement the complete UI to service path, verify meaningful behavior, run applicable browser/native checks, and package for the target operating system. Record failed or unavailable checks accurately. Review the source diff with the user before installing. App installation is a separate explicit action in the desktop client; agent tools and surfboards do not grant installation rights.

On macOS, **Install and restart** performs the complete sequence: transfer a bounded authenticated snapshot of saved, unignored source to the Mac, confirm running npm from that source, install locked dependencies, package and verify the app, then request the existing native confirmation before replacement and restart. Build cancellation or failure stops before replacement. It is one main-page action, with native confirmations at the source-execution and restart boundaries. Agent tools and surfboards do not grant installation rights. If the user asks for a preview without installation, build/test separately and leave this button untouched.

The source checkout and internal project still exist even though the Projects sidebar omits the app-source entry. Do not claim code lives or executes only on GitHub, or remove the underlying project, chat records, or source folder. Unsaved buffers and ignored files are not included in the transferred snapshot. A remote workspace can differ from the Mac. A successful preview or local package is not evidence that the running app changed; confirm the target app's reported build after an authorized installation.
